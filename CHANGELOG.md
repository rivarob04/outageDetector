## [Unreleased]

### Added
- Phase 6: outage map (MapLibre with a bundled offline Natural Earth basemap, optional `PULSE_MAP_STYLE_URL`), with provider regions colored by state, problem regions as shape glyphs, agents and this hub (`PULSE_HOST_LOCATION`), a details panel, provider filter and a 24-hour replay slider. Vantage agents: `pulse agent`, HMAC-signed push with timestamp/nonce replay protection, derived per-agent secrets, admin UI with a one-time token and compose snippet, revoke/delete, offline/stale handling, results feeding the verdict engine, and `deploy/docker-compose.agent.yml`.
- Phase 5: the dashboard UI. It has a one-sentence "is it down, or is it me?" verdict, incident banners, tiles with state glyphs (shape + color), scope badges, latency traces and 90-day bars, filters/search/sort/density, a service detail page with a "Why it's marked …" panel, timing-breakdown charts, components, incidents and agent results, a catalog browser with a custom-service form, incident history with MTTR, and settings (appearance, monitoring, import/export, password). Also dark/light/system/high-contrast themes, 1/2-column phone layout, PWA (manifest + service worker), keyboard shortcuts, kiosk mode (`/?kiosk=1`), demo mode (`PULSE_DEMO=1`), screenshots, vitest and Playwright smoke tests in CI.
- Phase 4: full database schema (Alembic 0002, SQLite + Postgres), store layer, the monitor (feed polling, probes, canaries, verdicts, 5-minute/daily rollups, retention), REST API `/api/v1` with OpenAPI docs, server-sent events, admin auth (setup code or env bootstrap, scrypt hashes, signed session cookie, CSRF, login rate limit), trusted-header auth for Authelia/Authentik, runtime-editable settings, config-as-code (`pulse.yaml`), import/export, and measured DB sizing (docs/DATABASE.md).
- Phase 3: HTTP probes with DNS/connect/TLS/TTFB timing, DNS probes comparing the system resolver with public resolvers, TCP connect and TLS-expiry probes, an SSRF guard (also applied to redirects) for user-supplied targets, connectivity canaries, latency baselines, an asyncio scheduler (jitter, bounded concurrency, backoff, no overlap) and the pure verdict engine (states, scopes, reasons, flap protection) with a decision table in docs/verdict.md and 41 table-driven tests.
- Phase 2: status-feed adapters (Atlassian Statuspage, status.io, AWS Health, Google Cloud, Google Workspace, Slack, Apple, Heroku, RSS/Atom); a polite HTTP client (UA, per-host spacing, retries, ETag/Last-Modified); a 53-service catalog validated by schema, with 165 map regions; `pulse catalog verify` and a weekly **Catalog verify** workflow that records live payloads as contract-test fixtures (52/53 verified on first run).
- Phase 1: FastAPI backend skeleton (settings, JSON logging, /healthz, /readyz, Alembic), React + Vite + Tailwind UI skeleton, multi-stage multi-arch Dockerfile, docker compose with postgres/mqtt/agent profiles, Makefile, CI (lint, typecheck, tests on SQLite + Postgres, compose smoke test) and GHCR release workflow.
- Phase 0: product spec, spec review, architecture, roadmap and the CLAUDE.md working agreement.
