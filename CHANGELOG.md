# Changelog

All notable changes to this project are documented here. Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), versioning: [SemVer](https://semver.org/).

## [Unreleased]

### Added
- Canadian ISPs in the catalog (Network): **Cogeco** (outage API), **TekSavvy** (its Google My Maps outage tracker), **Bell** (Bell has no feed; follows the DSL/Bell Fibre outages TekSavvy maps), plus checks-only **MNSi Telecom** and **Rogers** (no public status data).
- `PULSE_POSTAL_CODE` (also in Settings → Monitoring): report ISP outages at your address. Cogeco is asked for that postal code; TekSavvy/Bell only count outages in the same forward sortation area.
- Adapters `cogeco` and `mymaps`, and `options.postal_url` for feeds that are only published per postal code.

### Fixed
- Link-styled primary buttons (e.g. "Add services" on the empty Status page) had invisible text: the global link colour rule was unlayered and overrode `.btn-primary`. It now lives in `@layer base`.

### Changed
- Compose files: `PULSE_HOST_PORT` now sets the published host port and `PULSE_PORT` the port Pulse listens on inside the container (e.g. `3012:3000`). Healthchecks follow `PULSE_PORT`. Previously `PULSE_PORT` set the host port.
- `PULSE_TRUSTED_PROXIES` default no longer includes `10.0.0.0/8` and `192.168.0.0/16` (security).
- `PULSE_RETENTION_5M_DAYS` default is 30 (was 90 in the spec) after measuring storage.
- Removed the unused `PULSE_AGENT_NAME` (the hub names agents).

### Added
- Dockhand deployment: image-only compose files in `deploy/dockhand/` (Pulse, Pulse + Mosquitto, agent), docs/DOCKHAND.md, an **Image** workflow publishing `ghcr.io/rivarob04/outagedetector:edge` and `:sha-*` (amd64 + arm64), and a CI step that deploys the Dockhand files against the freshly built image.
- Phase 9: security headers (strict CSP, frame denial, nosniff, referrer and permissions policy, HSTS when secure), DNS-rebinding protection for user-defined checks, narrower default trusted-proxy ranges, Trivy image scan + pip-audit + npm audit in CI, the MapLibre 6 / React Router 7 upgrades (fixing published advisories), compact in-memory check history (10× less memory), a load test (`tools/perf_test.py`, docs/PERFORMANCE.md), portable `pulse backup`/`pulse restore` (SQLite ↔ Postgres), `pulse migrate --downgrade`, the optional public-IP header, full README, configuration reference (with a drift test), security threat model, reverse-proxy guide, FAQ, CONTRIBUTING, issue/PR templates, MIT license and GitHub release notes from this changelog.
- Phase 8: upstream correlation advisories (`depends_on`, region-aware), a time-of-day latency anomaly detector (EWMA vs. hourly median/MAD from 7 days of rollups, with fallback), community chatter spike detection (Hacker News, Reddit, Bluesky; off by default, advisory only) and the "before they admit it" lead-time metric, all behind feature flags with tests. See docs/SIGNALS.md.
- Phase 7: alerts through Apprise (80+ services) and HMAC-signed webhooks, with rules for severity, scope, services/categories, quiet hours with time zones, cooldown, recovery messages and a daily digest. Alerts pause while offline and send one summary afterwards; there's a test button and a notification log. Integrations: Prometheus `/metrics` (optional token) with a Grafana dashboard, MQTT bridge with Home Assistant discovery (compose `mqtt` profile; live-tested against Mosquitto in CI), Atom incident feed, iCal maintenance feed, SVG badges, and an optional public `/status` page.
- Phase 6: outage map (MapLibre with a bundled offline Natural Earth basemap, optional `PULSE_MAP_STYLE_URL`), with provider regions colored by state, problem regions as shape glyphs, agents and this hub (`PULSE_HOST_LOCATION`), a details panel, provider filter and a 24-hour replay slider. Vantage agents: `pulse agent`, HMAC-signed push with timestamp/nonce replay protection, derived per-agent secrets, admin UI with a one-time token and compose snippet, revoke/delete, offline/stale handling, results feeding the verdict engine, and `deploy/docker-compose.agent.yml`.
- Phase 5: the dashboard UI. It has a one-sentence "is it down, or is it me?" verdict, incident banners, tiles with state glyphs (shape + color), scope badges, latency traces and 90-day bars, filters/search/sort/density, a service detail page with a "Why it's marked …" panel, timing-breakdown charts, components, incidents and agent results, a catalog browser with a custom-service form, incident history with MTTR, and settings (appearance, monitoring, import/export, password). Also dark/light/system/high-contrast themes, 1/2-column phone layout, PWA (manifest + service worker), keyboard shortcuts, kiosk mode (`/?kiosk=1`), demo mode (`PULSE_DEMO=1`), screenshots, vitest and Playwright smoke tests in CI.
- Phase 4: full database schema (Alembic 0002, SQLite + Postgres), store layer, the monitor (feed polling, probes, canaries, verdicts, 5-minute/daily rollups, retention), REST API `/api/v1` with OpenAPI docs, server-sent events, admin auth (setup code or env bootstrap, scrypt hashes, signed session cookie, CSRF, login rate limit), trusted-header auth for Authelia/Authentik, runtime-editable settings, config-as-code (`pulse.yaml`), import/export, and measured DB sizing (docs/DATABASE.md).
- Phase 3: HTTP probes with DNS/connect/TLS/TTFB timing, DNS probes comparing the system resolver with public resolvers, TCP connect and TLS-expiry probes, an SSRF guard (also applied to redirects) for user-supplied targets, connectivity canaries, latency baselines, an asyncio scheduler (jitter, bounded concurrency, backoff, no overlap) and the pure verdict engine (states, scopes, reasons, flap protection) with a decision table in docs/verdict.md and 41 table-driven tests.
- Phase 2: status-feed adapters (Atlassian Statuspage, status.io, AWS Health, Google Cloud, Google Workspace, Slack, Apple, Heroku, RSS/Atom); a polite HTTP client (UA, per-host spacing, retries, ETag/Last-Modified); a 53-service catalog validated by schema, with 165 map regions; `pulse catalog verify` and a weekly **Catalog verify** workflow that records live payloads as contract-test fixtures (52/53 verified on first run).
- Phase 1: FastAPI backend skeleton (settings, JSON logging, /healthz, /readyz, Alembic), React + Vite + Tailwind UI skeleton, multi-stage multi-arch Dockerfile, docker compose with postgres/mqtt/agent profiles, Makefile, CI (lint, typecheck, tests on SQLite + Postgres, compose smoke test) and GHCR release workflow.
- Phase 0: product spec, spec review, architecture, roadmap and the CLAUDE.md working agreement.
